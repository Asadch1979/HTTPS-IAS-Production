## 6. Defect Register

### IAS-UAT-001 — Critical — Incomplete audit criteria persisted as successful

- Module/screen: Planning / Audit Criteria
- PPNO/context: 125022 / Role 11 / Entity 112248 / Context 993
- Steps: Select Period 6 and Entity Type 10; leave Auditable Entity and Frequency unselected; enter Days 5; Save.
- Expected: Client and server reject missing auditable entity/frequency; no Oracle row or success audit event.
- Actual: Criterion 689 created with `ENTITY_ID=0`, `FREQUENCY_ID=0`; success message and `AUDIT_CRITERIA_CREATED` success event recorded.
- Controller/API: `ApiCallsController`, audit-criteria create API
- Oracle: `PKG_PG.P_ADDAUDITCRITERIA`; `T_AUDIT_CRITERIA`
- Recommended fix: Enforce positive IDs in request validation, controller, and package before insert; audit only after validated business success.

### IAS-UAT-002 — Critical — Observation detail workflow blocked by invalid Oracle package — Resolved / Retest Passed

- Module/screen: Management Audit / Manage Observation / View Memo
- PPNO/context: 125031 / Role 10 / Entity 112248 / Context 1363
- Record: Engagement 2787, Observation 62960
- Expected: Observation detail loads for edit/submission.
- Actual: `IAS-ERR-00004`; `PLS-00905: object ZTBLAIS_PROD.PKG_AE is invalid`.
- Controller/API: `ApiCallsController.get_dept_observation_text`; `POST /ApiCalls/get_dept_observation_text`; Page ID 413
- Stack location: `DBConnection.AE.cs:270` via `GetObservationResponsiblePPNOs`, then `DBConnection.AR.cs:1350`
- Resolution evidence: On 2026-09-05 the package specification and body were `VALID`, `USER_ERRORS` returned zero rows, and the same View Memo action loaded Observation 62960 successfully.
- Status: **Closed for this tested API path**. Broader regression of every `PKG_AE` caller remains advisable.

- Expected: Validation message shown and entered values preserved.
- Actual: Engagement selection resets and all observation data is lost.
- Recommended fix: Do not reload/reset the dashboard on validation failure; preserve selected engagement and form model.

### IAS-UAT-007 — Critical — Standalone Manage Observations suppresses all team-lead actions — Fix Implemented / Partial Retest

- Module/screen: Execution / Manage Observations
- PPNO/context: 125031 / Role 10 / Entity 112248 / Context 1363
- Record: Engagement 2787, Observation 62960, status Created
- Expected: An authorized team lead can edit the memo and submit or drop the created observation.
- Actual: The grid exposes only View Memo and the modal exposes only Close. No edit, Submit to Auditee, or Drop Observation action is rendered.
- Live-page evidence: The DOM contains no `maIsTeamLeadField` and no action controls for Observation 62960.
- Code evidence: `Views/Execution/manage_observations.cshtml` does not render `maIsTeamLeadField`; `Views_Execution_manage_observations.js` makes every management action conditional on that field. The equivalent Management Audit partial does render it.
- Recommended fix: Supply a server-derived team-lead authorization flag to the standalone view (or perform the authorization server-side) and add server-side enforcement to all mutation APIs; regression-test both authorized and unauthorized team members.
- Resolution: The standalone engagement options now carry the server-derived assigned-lead flag. Edit, Drop, and Submit to Auditee are conditionally exposed from that flag, and all three mutation APIs independently return HTTP 403 to non-leads.
- Negative retest: **Pass** — PPNO 125031 can view Observation 62960 but, because this user is a member of Team 529 rather than its assigned lead, no Edit/Drop/Submit controls are displayed.
- Positive retest: **Pending test data** — Engagement 2787 is assigned to lead PPNO 139986, which is not one of the 34 supplied/reset UAT accounts.
