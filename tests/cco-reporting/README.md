# CCO Phase 1 checks

Run from the repository root. The application remains .NET 8; this console harness uses .NET 9 to match the existing System.Text.Json dependency graph.

```powershell
dotnet build AIS/AIS.csproj --no-restore -v quiet
dotnet run --project tests/cco-reporting/CcoReporting.Checks.csproj -- --eligibility-output "$env:TEMP/cco-endpoint-eligibility.json"
git fetch --depth=1 origin 1239d510f913cef79c98ef91d2e7eaad090c480c
node --test tests/cco-reporting/source.test.cjs
node tests/cco-reporting/client.browser.cjs "$env:TEMP/cco-endpoint-eligibility.json"
```

Playwright and Chrome must be installed; bundled Node packages can be exposed through NODE_PATH on the desktop host. The source test pins the public GitHub PR base, not a local setup commit. Full clones normally already have it; the fetch command supplies it for shallow checkouts.

The compiled checks invoke the actual public lifecycle action and assert its CCO denial. For permitted summary/distribution and B/C/D routes they invoke the production private execution/authorization pipeline with only the final data-reader delegate replaced by a sentinel. Session, perspective, page/API permission, view eligibility, date validation and scope narrowing execute unchanged. This verifies eligibility without an Oracle connection; it does not establish successful IAS data reads. No controller production code is modified for these probes.

Browser fixtures consume the eligibility manifest generated by those compiled probes and the actual CCO dataset/KPI definitions. Unsupported endpoints receive a denial instead of mocked success. Payloads remain fixtures. Report D checks its existing authorized Report C benchmark, canonical view and identical dates. Successful live reads, data reconciliation, real permission grants, context revocation and export acceptance still require approved staging.
