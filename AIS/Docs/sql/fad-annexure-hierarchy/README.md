# Annexure-driven FAD Risk Register implementation

Prepared source changes only. No database scripts have been executed and no testing activities were performed. This document does not assert deployment readiness.

## Implemented

The register reads Main KPI → Package → Process → Risk Rating Procedure → existing IAS Annexure. Source codes are copied exactly, without case conversion or whitespace normalization. The four staging hierarchy codes drive all relationships. Final Rating worksheets are not used by this import or browser.

Schema review used `AIS/Docs/Data_Structure/Table_Structure_for_Codex.txt`, `Tables.txt`, and the checked-in `PKG_FAD_RISK.sql`. They show globally unique hierarchy codes, existing Process → Sub KPI and Procedure → Process foreign keys, 200-byte descriptions, required weights and gravity, and the legacy duplicate Annexure master / MAP_ID relationship. Live schema review remains outstanding.

`T_RISK_FAD_PACKAGE` is a shared-primary-key extension of `T_RISK_FAD_KPI_SUB`: its `PACKAGE_ID` is the real existing Sub KPI ID. Names, codes and Main KPI relationships stay in Sub KPI, avoiding a second conflicting copy. The table is created only if absent. Process gains a nullable package foreign key and an equality constraint requiring it to agree with its existing Sub KPI relationship. Historical processes outside the approved source retain NULL. Procedure IDs, parent IDs and existing constraints remain intact. Description columns widen to 4000 bytes; import rejects longer strings rather than truncating them.

The new Annexure map uses `(SUB_PROCESS_ID, ANNEXURE_ID)` as primary key, references `T_AUDIT_CHECKLIST_ANNEXURE.ID`, and enforces unique source codes and IAS IDs for this one-Annexure/one-procedure approved catalog. Full violation text is CLOB; source code and risk classification are retained separately from the operational code. No duplicate Annexure master or legacy MAP_ID is used.

The migration locks the source and target configuration during its transaction, resolves exact codes or separately approved aliases, inserts parents before children, and reuses existing IDs. Only the new nullable package link is populated on existing rows. Existing names, weights, gravity, activation and parents must agree exactly or the entire transaction rolls back. Reruns accept identical records. It uses only the four sequences already named in the checked-in package, never MAX(ID)+1 or new sequence names. Sequence increments themselves are not transactional.

The MVC register endpoint uses the existing `RiskAction` authentication, session-revocation and API-permission checks; global guards remain unchanged. The Razor/JavaScript interface cascades selections and displays all procedures and Annexures for a process, with optional procedure filtering. It renders descriptions using text nodes. Configuration is now browsed read-only; old configuration save endpoints reject writes, and legacy Annexure save package signatures remain but reject duplicate-master writes. Existing assessment routes, versioned scoring SQL, assessment data, entity scoping and reporting cursors remain unchanged.
