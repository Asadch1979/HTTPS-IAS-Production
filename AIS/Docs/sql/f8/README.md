# PL/SQL Developer SQL Window (F8)

Open **one numbered file at a time** in a SQL Window and execute that unit with
F8. Package specs, bodies, views and anonymous blocks are individual units.
There is no standalone `/` delimiter, `SHOW ERRORS`, `WHENEVER`, `SET` or `SPOOL`
in these files. Do not paste the original SQL*Plus deployment script into the
SQL Window. The parent-directory files retain their SQL*Plus/Command Window use.

After **each** unit, run `validate_errors.sql` and `validate_status.sql` separately.
Stop on any errors or INVALID/missing expected objects; retain error output.
Oracle can create an invalid package without raising a client execution error.
Anonymous validation units use explicit exceptions; do not suppress those errors.
DDL auto-commits: capture existing definitions and review differences first.
Nothing here runs automatically or grants permissions.

Order for a full deployment of the referenced dashboard changes:

1. Existing DBA-maintained `V_IAS_ENTITY_REPORTING_IDS`,
   `V_IAS_ENTITY_REPORTING_NAMES`, entity/period/plan/engagement tables and
   existing `V_EXEC_KPI_LIFECYCLE`, compliance history/report-source dependencies.
2. `snap_audit_division_scope/01.sql`, then `02.sql` (spec/body).
3. `PKG_EXEC_DASHBOARD/01.sql` through `04.sql` (entity view, para view, spec, body).
4. `PKG_EXEC_REPORTS/01.sql`, then `02.sql` (spec/body).
5. `PKG_HEAD_AUDIT_MONITOR/01.sql` onward in numeric order (legacy compatibility
   view, office hierarchy, engagement scope, spec, body, explicit validation).
6. Review `head_audit_dashboard_menu/01.sql` before executing. This changes only
   the existing page 1000401 registration, accepting either its old Review path
   or canonical monitoring path. Inspect the affected row, then execute `02.sql`
   (COMMIT) only if correct; otherwise execute ROLLBACK instead.

For the Head of Audit upgrade alone, if the existing executive dependencies are
already valid, only steps 5–6 are required. There is no need to redeploy CIA/CCO
packages merely to upgrade this page.

For production `PKG_RPT` extraction, run `extract_pkg_rpt_spec.sql`,
`extract_pkg_rpt_body.sql` and `extract_pkg_rpt_arguments.sql` separately. Save
the complete CLOB results using PL/SQL Developer's CLOB editor/export operation.
No SPOOL is required. Do not replace PKG_RPT with the legacy standalone
`R_IAS_PARA_POSITION.sql`.

Numbered units are generated by `node scripts/generate-f8-sql.cjs`. Regenerate
after editing source SQL and verify equivalence before deployment. Source
checks do not establish live Oracle compilation; target Oracle/UAT is required.
