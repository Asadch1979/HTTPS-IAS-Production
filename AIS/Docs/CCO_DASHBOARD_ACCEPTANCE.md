# CCO Performance deployment and acceptance

Field Audit (B) uses the Report C GM and region/reporting-entity rules. Management Audit (D) uses the Report E active Group/Division mapping and shows the audited department under its division. The package returns Group, Division, Field GM, population and combined totals. Unknown or conflicting paths remain in the all-Group report and cannot match an individual Group selection. A missing settlement denominator displays N/A.

## Deployment order

1. Confirm the installed V_EXEC_REPORT_SOURCE, V_EXEC_ENTITY_SCOPE and V_IAS_ENTITY_REPORTING_IDS_Group_reports contracts and the active IAS context table. Inspect the read-only preflight and source duplicates before activation. **PKG_EXEC_DASHBOARD.sql is frozen and excluded from this Performance deployment.** Any separate rollout of its already-tested version for Critical Observations follows the existing approved process.
2. Compile only `sql/PKG_EXEC_CCO_PERFORMANCE.sql` under the established IAS reporting owner. Verify its signature, the existing `T_USER_SESSION` columns and `USER_ERRORS`. If the approved package owner differs from the existing application DB login, grant that existing login EXECUTE on this package only and create a private synonym if required. Do not grant direct source-table access.
3. **No new Oracle account is required.** The reader uses the current IAS `DatabaseConnection()` with `ConnectionStrings:DBUserName`, `DBUserPassword` and `DBDataSource`, as other CCO reports do. Remove the obsolete dedicated-connection requirement. The application still checks role 38 or verified Super User role 1, page 1000302, exact API permission and active session. The package independently verifies `P_SESSION_ID` against `T_USER_SESSION` and the matching active context, role and posting. No PUBLIC grants, `EXECUTE ANY PROCEDURE` or new database roles. The feature flag is not an authorization mechanism.
4. Register the exact GET /api/CcoCompliance/GetOrgPerformance API against page 1000302, initially inactive. Stage the exact role mappings for CCO role 38 and Super User role 1, then activate only for the approved staging verification and refresh permission caches through a new session. Keep the existing GetCriticalItems and GetFunctionPosition registrations intact.
5. Deploy the application with CcoReporting:PerformanceEnabled unset or false. Enable the flag only in isolated staging after the database reader and grants have been checked. Leave production disabled until the acceptance checks below pass.

## Reconciliation and security acceptance

- Run Performance, Report C (B) and Report E (D) for identical dates and the same authorized portfolio. Compare B population totals and B totals by GM/reporting entity with Report C. Compare D population totals and D figures by verified Group and Division with Report E. For both, verify opening, additions, total, settlements, outstanding, high-risk outstanding, settlement percentage and residual. The residual is outstanding minus (opening plus additions minus settlements). Net backlog change is outstanding minus opening. Compare Overview using the same eligible COM_IDs and document any source-clock or population differences.
- Check duplicate source rows for each COM_ID. Identical movement evidence counts once even if paths conflict. Conflicting movement versions or a COM_ID in both B and D fail the affected period rather than producing a misleading grand total. Investigate and resolve the source discrepancy before activation. Reconcile the combined totals with the disjoint B and D populations. Record missing paths and ensure their figures remain in the all-Group totals.
- Exercise all Groups, a verified Group, invalid and duplicate selectors, multiple GM offices and departments, ambiguous and missing paths, empty results, zero denominator, exactly MaxRows rows and one additional row. Performance returns a specific bounded-result error on overflow. Check expandable rows, sorting and search on desktop and mobile. Verify Critical Observations pagination separately as a regression.
- Verify that an Oracle principal without EXECUTE cannot call this package. Using the existing IAS application DB login, reject unknown, revoked or mismatched session IDs, context IDs, roles and postings with ORA-20811. Verify API denial with missing page/API grants, unauthorized role, unverified role 1 or revoked session. Do not expose Oracle exception details to clients.

Oracle compilation, database grants, authorized response reconciliation and live security acceptance require the approved staging environment.
