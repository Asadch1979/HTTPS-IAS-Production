## Changes

- Invalid POSTs return the existing Status/Message validation payload with HTTP 400 instead of inferring a Razor view from the action name. Explicit form handlers can reconstruct their originating view. SaveFieldAuditInputs checks ModelState before writes and redisplays an allowlisted GET view with submitted field values and validation errors. SaveNarrativePara works without an AJAX header; its fetch handler accepts both JSON naming conventions.
- Both field-audit DTOs were inspected with real MVC model-binding tests. Nullable reference types are not enabled in this project, there are no Required annotations on these DTOs, blank draft narratives are intentional, ParaNo is optional and section-only forms need not submit Fields. No global validation or required business validation was removed. FINALIZE still checks narrative completeness.
- Add-to-Draft accepts only status 3 and transitions to 5. The existing assigned-user check and observation FOR UPDATE remain. An optional trailing P_ENG_ID compares request context with the actual observation engagement; old callers may omit it, but assignment is always checked against the actual engagement. The engagement row serializes draft numbering, including equivalent zero-padded numbers. The existing memo/draft-number edit procedure uses the same lock and comparison, preventing a concurrent renumber from bypassing uniqueness; its unexpected errors now propagate to centralized monitoring instead of returning SQLERRM to the user. ORA-20006 returns a controlled rejection; ORA-20007 reports mismatched context. Unexpected exceptions still propagate. All five frontends guard eligibility and duplicate clicks.
- P_audit_pre_Concluding locks its parent observation before authorization and either MERGE, uses sequences for IDs, and commits heading/gist/recommendation together. Failure rolls back and rethrows. P_Finalise_para is the only other recommendation INSERT found in the repository; it now shares the sequence and parent lock. Its other business logic is unchanged. The existing C# success message is recognized explicitly; business rejection or empty response is not success. JSON is serialized by MVC, and failed frontend saves retain input.
- History SQL uses the same parenthesized Asia/Karachi conversion as F_LOCAL_DATE. The helper is private to the body, so the SQL cursor uses its expression without expanding the public interface. All columns, optional parameters and >= start / < end boundaries remain. Both scheduler package copies match. Scheduler job definitions, poller, workers and history are unchanged.
- Existing occurrence history already stores each request's identity and technical details. GET_SYSTEM_ERROR_DETAIL now returns those details; the UI distinguishes the retained first identity from the latest recorded occurrence, including trace, scope IDs and technical details. Each historical row exposes its own details. No schema extension or changes to fingerprints, notification claims or resolution are needed. List identity filters are explicitly labeled first-occurrence filters; IP is labeled latest.

## Deployment order (DBA, isolated QA first)

1. Back up the four current package specs/bodies. Run sql/preflight_production_error_remediation.sql as the owning schema and retain its output. Review UQ_OBS_GIST's exact columns, all unique keys, triggers and external writers. Stop if the schema or MERGE key assumptions do not match. Read-only metadata confirmed UQ_OBS_GIST constrains OBS_ID in the configured ZTBLAIS_PROD schema; bootstrap requires that exact key. Recheck the deployment target because the reported exception names ZTBLAIS.
2. Stop all writers to both observation gist/recommendation tables for a maintenance window. Run sql/deploy_observation_gist_sequences.sql. New sequences start above historical IDs. Reruns verify configuration and next value; an existing lagging sequence stops deployment for DBA forward-only advancement. DDL commits, so table locks alone cannot protect bootstrap. Do not resume old MAX+1 writers.
3. Run sql/deploy_production_error_remediation_packages.sql in SQL*Plus or SQLcl. It replaces packages in this order: **PKG_HD - prod.sql**, **PKG_AR - prod.sql**, **PKG_LG.sql**, **deploy_ias_scheduler_package_only.sql**. Each spec/body is followed by compilation/status checks that stop the script on failure. The corrected production-based AR/HD files preserve all unrelated logic from the supplied snapshots; use them for this rollout rather than substituting the canonical files. PKG_AR adds the backward-compatible optional final argument P_ENG_ID; PKG_LG appends TECHNICAL_DETAILS to the history cursor.
4. DO NOT run the historical schema DDL at the beginning of PKG_IAS_SCHEDULER.sql. Do not recreate/register/reset jobs or clear history. The runner includes the scheduler package-only replacement.
5. Check USER_ERRORS and USER_OBJECTS for all four packages and invalidated dependents. Require valid spec/body and no compilation errors before continuing. Run the QA scenarios below, then deploy the application/static assets and resume writers only after approved verification.

No deployment scripts or database writes have been executed. Only read-only metadata and timezone-expression SELECTs were run. Sequence creation is additive DDL; it does not modify historical records or constraints. Do not reset sequences on rollback. An application rollback may retain the updated backward-compatible packages; rolling back sequence-aware writers requires another planned migration to avoid allocator collisions.
